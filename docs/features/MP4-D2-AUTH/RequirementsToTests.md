## 2. Environment and fixture contract

Use Node 24/npm 11. Before a database-connected command, require an explicit, parsed PostgreSQL URL with loopback host (`127.0.0.1` or `localhost`) and database name ending `_test`; reject missing/remote/malformed/non-PostgreSQL targets and query/fragment tricks. Validate before starting a server, connecting, migration, seed or cleanup. Test the guard with query parameters that could override host/database and with inherited `VITE_API_BASE_URL`; neither may redirect a synthetic run. Set `TEST_DATABASE_URL` for integration, `E2E_TEST_DATABASE_URL` for opted-in browser tests, and the same verified `DATABASE_URL`/`DATABASE_URL_POOLED` for preparation/runtime. Do not publish full connection URLs. Use an owned disposable instance/namespace; leave the pre-existing service on port 5433 and unrelated processes intact.

Prepare migrations and required seed only on that verified target, checking each exit status before proceeding. `test:integration` does not provision it. Seed learner/instructor records are not usable password credentials. Give every test a unique synthetic `@example.test` identity and unique provider subject; snapshot IDs, roles, related rows and account keys before mutations. Clean only owned fixtures, including namespaced intents/outbox items. Where schema relationships permit, use a related-data sentinel and assert its stable owner; always assert actual Account/Session relationships. Legacy collision fixtures deliberately bypass the canonical application writer only in the isolated rehearsal setup.

Browser origin is `http://127.0.0.1:5173`, with auth and API routed consistently through that origin and an identified direct backend. Refuse unknown server reuse. Explicitly isolate Google, SMTP and OAuth-proxy credentials from inherited environments. The current opt-in no-SMTP browser fixture is insufficient for verification/recovery: **propose** a test-only local server fixture injecting the existing email callback into a private captured outbox. Expose retrieval only to the test controller through an owned fixture channel, never a production/public debug endpoint. Supply synthetic email configuration to enable the required delivery path. The browser receives links from this fixture and navigates them normally; do not mark email verified or insert reset tokens directly in a full-journey case. A test-only Google transport fixture is also proposed, with installed 1.7.14 provider types; no new production provider shortcut.

Run every BW journey in existing `chromium` (Desktop Chrome) and `mobile-chromium` (Pixel 7) projects, with keyboard/semantic role queries. Supply a clock seam for expiry and barriers/latches for races. Do not sleep and hope two requests overlap. Use separate cookie jars/clients and independent database connections, hold both contenders immediately before the contested insert/claim/consume, release deliberately, and assert committed postconditions after both settle. Use bounded timeouts and `finally` cleanup; restore spies/fault seams between cases. Fault injection belongs at the selected adapter/delivery boundary and must not replace the real transaction/unique constraint being tested.
