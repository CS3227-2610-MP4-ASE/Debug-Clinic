## Synthetic fixtures

- **I1** owns questions and grades. **I2** is another instructor with their own question. **L1** and **L2** are unrelated learners. Display names are **Instructor One**, **Instructor Two**, **Learner One** and **Learner Two**. Use unique per-run synthetic account addresses under `example.test` and retain the generated IDs only in the test context. Use guest, expired or revoked cookies, wrong-role cookies and a valid cookie with a mismatched actor header as separate conditions.
- **F-Old** is L1's pre-feature final for I1's published **Count every item**, with a known submission time and a legacy Review. **F-New** is L1's later final for a distinct I1 question, submitted via the normal workspace. **F-Archive** is L1's final for a third I1 question, withdrawn after finalization. **F-L2** is L2's final on an I1 question. **F-I2** is L2's final for I2. **D-L1** is L1's saved draft on a different I1 question, with additional unsaved edits in the learner's editor. Use independent copies for grading and ungraded partitions so tests can run in any order.
- Give F-Old the problem **Fix the function to count every item.**, expected behavior **count([2, 4]) returns 2.**, code `def count(items):\n    return len(items)\n` and reasoning `Use the collection length.\n\nThe empty case is zero.\n`. The escape sequences represent literal line breaks. Include distinct context and answer strings on other finals, text containing markup in one fixture and distinguishable sentinel values for learner email, private solution/provenance, draft content and legacy Review comment. Verify allowlists and scan for sentinel values in raw responses, grading logs and visible content where appropriate. The instructor receives learner display name. The learner receives only their own result.
- Control submitted times to distinguish oldest/newest and prepare tied tuples spanning a 50-row page in isolated data. For ordering by save time, use public saves and wait for distinct authoritative times unless deliberately testing a tie. Grade values include boundary **1** and **10**, initial **6**, competing **7**, and correction **8**. Use unchanged snapshots and submission time from the original authoritative final reply as the comparison across later reads.

### HTTP with PostgreSQL

- **H01 · Read an eligible final and rehearse migration.** Start with one public behavior test. I1's cookie reads F-Old detail and receives its exact submitted snapshot, context and display name with grade null. Extend to an archived final and denied draft/foreign reads in separate red–green cycles. Apply the additive migration to empty and representative pre-feature targets. Recheck existing attempt HTTP and verify the old final grades normally. Use a separately labelled structural check for the score/revision checks, one-grade key, foreign key and retained legacy Review. Exercise pre-migration grading dependency failure and existing HTTP against the additive schema.
- **H02 · List projection, membership, order and cursor boundaries.** Verify exact response keys, row ownership, view membership and times using F-Old/F-New/F-Archive and D-L1. Page a tied-time boundary and compare literal expected IDs, order, count, no duplicates and terminal null cursor. Continue from a cursor whose row changes views, and refresh page one after a correction reorders an item. Reject malformed, oversized, wrong-scope cursors and unexpected or repeated query parameters. A cursor from another owner never broadens access.
- **H03 · Save and read the current grade.** Send score and `expectedRevision` over real instructor PUT, using null for a first grade. Confirm revision 1 and compact learner read on commit. Reject missing/extra fields, string numbers, fractional scores, 0 and 11, and invalid revisions, on both ungraded and graded finals. Correct 6 to 8 and require one current grade with incremented revision and later save time. Matching-revision same-score save preserves revision/time. Verify stale same-score rejection in H04. Seed the integer revision ceiling and verify a different-score write receives the safe terminal conflict. Compare the original attempt snapshot, time and revision through existing HTTP.
- **H04 · Real competing writers.** Release two requests from independent authenticated I1 clients against the same final, first with null and then in a separate run with the same saved revision. Require one successful changing write and one `409 CONFLICT` with `NOT_APPLIED`, regardless of the winner. An authorized read identifies exactly the winner's score and one revision advance. In an ordered stale-form variant, save 6, reject stale 8 and stale 6, then apply 8 only with the reviewed revision. Advance the grade again before a different deliberate save and require another conflict.
- **H05 · Definitive rejection and uncertain transport.** Exercise an established pre-write/rollback failure on isolated data and verify `503 DEPENDENCY_UNAVAILABLE` with `NOT_APPLIED`, plus unchanged learner grade or null. Separately, use an owned PG transport fault patterned on the existing F02 lost COMMIT acknowledgement check. Withhold a real commit acknowledgement from the grading database client, verify the emitted PUT error carries `UNKNOWN`, then read the committed result through healthy authorized GET. Count one write. C03 separately checks a dropped HTTP reply after committed success. [Baseline PG transport fault](../../../tests/integration/f02-publication.test.ts)
- **H06 · Authorization, raw transport and privacy.** Test each list, detail and compact read with its permitted role. For read and PUT, use guest/revoked cookies, wrong roles, a mismatched actor header, foreign final, draft and nonexistent IDs, including after archive. Require safe 401/403 or uniform 404 as specified, no data in denial/error projections, and unchanged authorized results after rejected PUT. Exercise allowed/missing/foreign Origin, non-JSON, malformed/oversized JSON and PUT outcome tags. Verify `Cache-Control: private, no-store` and `Vary` on Cookie and existing Origin behavior, including applicable error paths. A valid grading GET with conditional validators returns complete 200 data. Check raw output and captured grading logs for sentinels. Recheck existing browse and attempt rejection after removal.
- **H07 · Shared-IP polling capacity and isolation.** Run real authenticated HTTP with ordinary limiter settings on an isolated PostgreSQL target. Use 11 synthetic learners with valid actor assertions and owned final attempts, one common proxy-aware IP, 12 scheduled compact GETs per learner in one minute, and representative ordinary app traffic. Expect all 132 poll reads and ordinary requests within their respective budgets to succeed. Separately exhaust one learner's poll allowance and verify another learner and ordinary routes retain their allowances. Exercise the dedicated IP ceiling, rejected requests counting against the ordinary IP budget and legacy route behavior, on separate limiter instances so the scenarios do not interfere. Record throughput, 429s and the tested envelope separately from the timed browser result. Never substitute the test-mode 10,000-request allowance for this check.

For H06, send unauthenticated OPTIONS requests for the credentialed compact GET and grading PUT, with `X-DebugClinic-Actor` among the requested headers. Verify that the allowed-origin preflight permits credentials and the header and exposes no submission data. Reject a foreign origin.
