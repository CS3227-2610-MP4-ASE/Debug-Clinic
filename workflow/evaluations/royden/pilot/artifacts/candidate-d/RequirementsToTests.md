# Requirements to tests — experimental acceptance draft

Status: **not human-approved SDD**. This is an implementation-time test plan, not a report of passing feature tests. No application code, database migration or feature tests were implemented or executed in this planning task. PRD.md defines R01–R15; TDD.md defines proposed mechanics; GrillingDecisions.md preserves COACH-01–15 evidence.

## Harness and evidence rules

Use baseline Vitest for contracts/coordinator units, Supertest for Express routes plus **real local PostgreSQL/Prisma** state and transactions, and Playwright for the React/MUI workspace. Use the backend offline fake AiProvider in every suite. Deny external transport in the harness and fail if any live network call is attempted. Do not replace database concurrency tests with in-memory maps, SQLite or mocked transactions.

Seed two learners A/B, an instructor I, published exercise versions V1/V2 with stage-labelled approved hints, a private solution sentinel, unrelated learner/work sentinels, and open/submitted attempts. Pin A's attempt to V1. Saved revisions have distinct code/reasoning sentinels. These are synthetic fixtures, not real-user data. Bounds, request windows and deadlines in tests are deliberately small fixture values, never claims about provider capabilities or production defaults.

The fake must expose invocation count, captured context, output/usage fixture selection, explicit start/complete barriers and cancellation behavior. Content repositories expose private-read counters separately from safe metadata reads. A controllable clock drives deadlines/recovery. Assert deterministic transitions using barriers or lock acquisition, not probabilistic sleeps. Each integration race uses independent database connections and inspects rows, ledger/reservations, stage counters, feedback rows and fake invocation count after completion. Browser disabling is supplemental evidence, never the concurrency mechanism.

## Planned tests

| ID / layer | Scenario and exact assertions |
|---|---|
| T01 / Supertest + DB | Anonymous request and expired/deleted Better Auth session return AUTH_REQUIRED/request ID. Private-content reads, fake calls, coaching rows and quota changes are all zero. Do not mock a valid body identity into authorization. |
| T02 / Supertest + DB | Instructor I, learner B and nonexistent attempt ID receive equivalent safe unavailable responses for A's endpoint. Forged user/role/body/header fields cannot authorize. Metadata lookup is allowed; source/reasoning/feedback/projection reads and fake calls remain zero. |
| T03 / Supertest + DB | A cannot poll/replay B's request ID or key, including guessing a successful receipt. Attempt state is checked before private reads. A may retrieve owned historical feedback tagged to its original revision; replay after save/submission does not generate or advance anything and is never marked current. |
| T04 / contracts + API | No saved revision, absent/blank reasoning (including whitespace), no saved code proposal, unpublished/missing projection or oversized inputs produce stable no-call errors. Server state, not client-supplied code/reasoning, determines eligibility. Strict body rejects extra stage/model/prompt/context/user fields and malformed IDs/keys/progress versions. |
| T05 / coordinator + DB | Attempt pinned to V1 sees only V1's published statement and stage-permitted approved hints despite V2 changes. Captured fake context contains current saved source/reasoning; contains no private solution sentinel, other learner sentinel, full solution or unrelated fields. Failure to obtain safe projection calls no AI. |
| T06 / coordinator + API + DB | Three separate valid operations on unchanged revision yield stages exactly 1,2,3, completed stages 1,2,3 and contiguous feedback/ledger. A fourth new key returns STAGES_EXHAUSTED with fake count still 3. Browser cannot skip or replay-select a stage. |
| T07 / coordinator + DB | Definite upstream failure, timeout, rate limit, quota, malformed output and validation failure at each stage advance nothing and create no application stage charge. Available provider usage remains recorded; retrying deliberately with a new key requests the same next stage. Each response has stable safe code/request ID. |
| T08 / DB fault injection | Fail the feedback/advancement transaction after provider success. No partial feedback/counter/ledger commit is observable. Fail the HTTP acknowledgement after a committed success; replay yields durable success with no provider or stage duplicate. Reconcile unknown commit result through the stored request, never regenerate. |
| T09 / DB + browser | Independently save a code edit and reasoning-only edit. Each creates a new immutable revision, completedStages=0 and incremented progressVersion while old feedback stays attached to old revision. Draft code is not silently saved by coaching; failed save cannot alter displayed saved revision. |
| T10 / DB race | Hold fake completion, save a revision, then finish old call. Old outcome becomes superseded with zero new-revision feedback/advancement; provider metadata remains honest. Reverse ordering: old success commits then save resets new revision. UI labels old result historical and preserves dirty work. Active guard persists until original completion/deadline and only its owner can clear it. |
| T11 / DB race + API | Block fake, commit explicit submit, release valid response: submitted remains terminal, no feedback/stage increment after submit. Reverse lock order: feedback may commit once then submit. Further edits/new keys are rejected with zero new calls. Historical same-key replay never submits/generates/advances. Repeat with save-v-submit and crash recovery while submitted. |
| T12 / DB concurrency | Send same key/fingerprint concurrently on independent connections. One admission, one fake invocation, one receipt and eventual identical saved result. Replay after response loss/restart increments neither provider dispatch, reservation nor stage ledger. Pending response never creates a second dispatch. |
| T13 / DB concurrency | Distinct keys for same attempt/revision/progress race. One gets active guard, other REQUEST_IN_PROGRESS, at most one fake call. After success, stale expectedProgressVersion fails; fresh progress explicitly advances only the next stage. Distinct attempts racing a shared learner quota cannot exceed its atomically reserved cap. |
| T14 / API + DB | Same key with changed revision/progress/body fingerprint gives IDEMPOTENCY_CONFLICT and zero extra dispatch/charge. Same opaque key under a different learner/attempt cannot disclose A's outcome. Fingerprint comparison precedes current-progress rejection for a legitimate successful replay. |
| T15 / clock + restart + DB | Persist DISPATCH_INTENT then interrupt before known result. Before deadline, replay is pending/no resend. At deadline recovery closes UNKNOWN once, clears matching guard, preserves possible provider charge and null unknown usage; duplicate recovery is harmless. A crash before dispatch intent safely closes/reconciles without inventing a provider success. No automatic send for uncertain intent. |
| T16 / clock + DB + browser | After UNKNOWN, same key returns saved UNKNOWN. Deliberate refreshed new-key action is separately admitted/accounted at same stage. Release old fake result after new request begins: old result cannot revive, store current feedback, advance or clear new guard. Browser explains unknown prior usage. Metadata-only late usage update cannot become a stage event. |
| T17 / unit + fake | Learner code/reasoning contains “ignore instructions”, pretend instructor messages, commands and solution requests. Captured role/data structure keeps them in untrusted data; no privileged tool/callback exists. Prior feedback comes only from same revision in deterministic order. Test shape/isolation, without claiming a fake proves live-model pedagogical safety. |
| T18 / contracts + unit | At each configured bound test just below/equal/above for code/reasoning/body/key bytes, context, feedback count and total/per-field output. UTF-8 multibyte fixtures expose byte/character mismatch. Optional old feedback is removed deterministically; mandatory source/reasoning/statement/hints are never silently truncated. Over-budget mandatory context rejects before dispatch. |
| T19 / unit + API | Wrong JSON type, missing/empty/unknown fields, nested instructions/actions, oversized fields, invalid encoding/envelope and malformed provider metadata fail bounded output validation safely. No stage/feedback persists and no raw provider body leaks into error/log. Server attaches authoritative stage/revision; model cannot set them. |
| T20 / Playwright + DB | Provider text contains HTML/script/event handlers, Markdown links and privileged-looking instructions. Assert exact text rendering, no injected DOM/script/navigation/network side effects, no code execution and unchanged grades, roles, publication, submission and instructor decisions. Schema may reject action objects; advisory copy remains visible. |
| T21 / unit + boot | Missing, nonfinite, negative or incompatible config fails closed; allowed zero retry count works. Bound deadline/lease/poll relationships; retries only when adapter proves no dispatch and always within retry/deadline caps. Fake tests use no real credentials/network. Stage count cannot be reconfigured away from 3. |
| T22 / API + DB + browser | Exhaust request-rate/quota reservations, deadline and retry limits. Stable recoverable errors include request IDs; call count respects caps, no counter advance, work preserved, appropriate wait/refresh/new-request action. Revision reset does not reset provider quotas. Replayed requests do not consume another reservation. Browser disconnect does not imply free cancellation. |
| T23 / DB + unit | Successful, failed, uncertain and replayed operations store correct request/revision/stage, prompt/model version, latency and outcome. Missing usage is null; known reported usage stored without guessing cost. Successful stage ledger once; failed/possible provider dispatch accounting remains separate. Negative/malformed usage metadata cannot corrupt totals. |
| T24 / Playwright | Empty saved work, blank reasoning, dirty edits, pending, error, stale, timeout/unknown, stage exhaustion and submitted states. Request button disabled when duplicate/unsaved/ineligible; meaningful retry preserves dirty work and saved revision. Refresh/reload recovers request receipt without duplicate calls or discarded edits. Save, coaching and final submission remain separate explicit actions. |
| T25 / telemetry + DB | Seed unique secrets/code/reasoning/prompt/output/cookie/credential sentinels in success, validation, denial and provider-failure paths. Capture app/access/provider/error/browser logs and metrics; assert none contain forbidden fields or sentinels. DB stores necessary owned validated feedback, not raw prompts/bodies. Before real users, add retention/deletion tests only after the owner chooses lifecycle semantics. |
| T26 / Playwright | Complete workflow keyboard-only, check focus/labels and live-region status. Mobile viewport reflows without inaccessible controls or feedback overflow. Empty/error/pending/exhausted/submitted copy is understandable and advisory; no redundant coaching controls or chat surface appears. |
| T27 / architecture review | Verify route uses existing Better Auth database session and backend AiProvider, shared Zod, real PostgreSQL/Prisma integration, existing save/submit lock seam and exactly two roles. No Python runner, tool dispatcher, authoring, instructor review, new IdP or deployment added. Review precise safe projection and absence of private aggregate fetches. |

## Evidence to collect when implementation is authorized

Record actual commands, versions, local DB setup/migrations and fixture seed, suite results, failed tests/remediation, schema constraints, race barrier traces, invocation counts, relevant DB state/ledger and sanitized screenshots/accessibility checks. Passing planned tests cannot be claimed from this document. No actual package commands are invented because the product repository was deliberately not inspected.

Human owner review must resolve draft API/replay semantics, quota units and TP-RECOVERY before implementation. Retention/deletion decisions remain required before real users. Production acceptance additionally needs live-provider capability/numeric-limit verification and quality/security evaluation under separate authorization; this offline plan supplies none of that evidence.
