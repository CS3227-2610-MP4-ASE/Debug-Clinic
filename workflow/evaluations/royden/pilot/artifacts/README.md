# Synthetic participant snapshots

These are verbatim experimental outputs, not product modules, approved feature
specifications, or executable application tests. Code/test files have a `.txt`
suffix to keep product tooling from discovering them. Markdown is intentionally
excluded from formatting so the archive retains the participant's original bytes.

- `candidate-a`: single-builder delivery.
- `candidate-b-code`: parallel implementation, followed by coordinator integration
  of acceptance tests from `candidate-b-tests`.
- `candidate-b-tests`: independent test interpretation and expected-red evidence.
- `candidate-c`: ordinary planning with normal oracle clarification.
- `candidate-d`: planning with grill-me/grilling and the same oracle.

Condition labels were withheld from the judge until scoring. Final reports retain
the initial delivery score and its checkpoint-evidence correction. The corrected
score stayed unchanged: a missing final integration command remained an evidence
gap in the scored handoff. See the pilot report for the actual integration command.
